# Review-77 residuals (D-122 / D-123) after the R4 deploy work (branch `r4-deploy`)

D-123 accepted the review-77 findings as a residual risk **for R3 only** and made the tooling
hardening a precondition of R4. This file lists every finding (D-122's list; the file:line
references are in `docs/consults/77-astra-review-r3-tooling-final.md` and
`docs/consults/77-sol56-review-r3-tooling-final.md`) and says whether the R4 deploy work closes
it. "OPEN" items were out of this work's scope (R4 plan §1.10 / consult 89): they are not fixed
here and stay an explicit, owner-accepted residual for the R4 test window, with the mitigation in
the RUNBOOK "R4 release" section.

| # | Severity | Finding (review 77) | Status | How / why |
|---|---|---|---|---|
| 1 | HIGH | A resumed deploy publishes a half-switched stack: `resume_attempt` checks only the api's revision before publishing (`remote-deploy.sh` resume path). | OPEN | Out of scope. Mitigation: the R4 deploy is attended; a killed deploy is re-run by hand and its output read (the new stack's `internal_checks` run before the publish). |
| 2 | HIGH | The backup timer and `restore.sh` race a rollback or a recovery: the operation lock (`.operation.flock`) is not held across dump → restore → validate. | PARTLY CLOSED | **Rollback: closed (R-2).** `rollback.sh` takes `$HLM_BACKUP_DIR/.operation.flock` before anything stops and holds it to the end, recovery included; `backup.sh` runs under it (`HLM_OPERATION_LOCK_HELD=1`); a held lock refuses the rollback before anything stops. Test: `test_release_convergence.py::test_rollback_refuses_while_a_backup_or_restore_holds_the_operation_lock`. **Deploy resume recovery (`resume_attempt`): OPEN** (out of scope); the normal deploy path already holds the lock from the live dump on. Mitigation: pause the backup timer during the attended deploy window (D-123). |
| 3 | HIGH | Daily rotation can delete the rollback safety dump, and a retry then cleans the journal without restoring. | CLOSED (R-2) | The safety dump is written to `$HLM_BACKUP_DIR/rollback/` (`backup.sh --rollback-safety`), a tier no rotation of any release touches (after an interrupted rollback the timer runs the PREVIOUS release's backup.sh/retention.py, so only a separate tier is safe from all of them); `retention.py` also never deletes a dump the release state still references (`rollback_safety`, `previous_dump`, `deploy_attempt.previous_dump`). After the destructive phase began, a recovery that finds the safety dump missing stops FAIL CLOSED: writers stay stopped, nothing restarts, no `end-rollback`, the journal stays open. Tests: `test_release_convergence.py::test_missing_safety_dump_after_the_destructive_phase_fails_closed`, `::test_daily_backups_after_a_killed_rollback_keep_its_safety_dump`, `test_backup_retention.py::test_rotation_and_prune_never_delete_a_dump_the_release_state_references`, `test_backup_lock.py::test_rollback_safety_dump_is_outside_rotation_and_journalled_dumps_survive_it`. |
| 4 | HIGH | The install and the deploy/rollback journals can deadlock each other (`install_llm_env.sh` does not refuse an unfinished `deploy_attempt` / `rollback_in_progress`). | OPEN | Out of scope. Mitigation (RUNBOOK): never run `install_llm_env.sh` while `python3 /opt/hlmemo/app/deploy/scripts/release_state.py get /opt/hlmemo deploy_attempt` (or `... rollback_in_progress`) prints anything; finish that operation first. |
| 5 | HIGH | The persistent image selection (`HLM_IMAGE` in prod.env) is not reverted when a resumed deploy recovers. | OPEN | Out of scope. Mitigation: after any recovered deploy, check `grep HLM_IMAGE /etc/hlmemo/prod.env` against the running api's revision before the next `up`. |

Tests: `test_llm_env_release.py::test_fingerprint_covers_the_r4_behaviour_keys_and_the_guard`, `::test_provenance_requires_both_the_api_and_the_librarian`. |

| 8 | MEDIUM | Extra `HLM_FALLBACK_PROFILE__*` overrides or an unreadable `--llm-env-file` fail open in `check_librarian.py evaluate`. | OPEN | Out of scope. Mitigation: `evaluate` prints every per-task fallback it runs with (`per-task fallbacks: ...`); read it in the install output. |
