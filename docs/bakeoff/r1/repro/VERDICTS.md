## Real but mis-described
- **F16(b):** the mechanism is not "new note's logical id is None at supersession time". Each close's `$0` points at a different new note, so it would never match `(dst, rel)` anyway. Accumulation comes from the same missing "supersede all prior card sources" rule as (a). `raw_links` has no temporal filter (read_queries.py:477), so even superseded links would still be listed without pagination. The error is also not "permanent": the budget can go up to 32000, so it takes about 400 closes, not 30.
- **F11:** on the VPS, `HLM_REGISTRATION_SECRET` is set (spec :331), and the secret check (devices.py:95) runs before the body read. So the unauthenticated vector exists only when the secret is unset. The trusted-device vector (revocation blocked, pool pinned) remains, and it is High because it defeats revocation.
- **F13:** spec §3 authorization order (1)-(3) lists project grants only and is silent on `device_scope`. The behaviour is a spec gap rather than a letter-of-spec violation, but it contradicts §4.4, "a row failing (a) does not exist for the caller".
- **F10:** rejected against PHASE0-SPEC, but D-015 ("deterministic skeleton at project creation") was not implemented or specified, and no decision logs the deviation, which CLAUDE.md requires. That is a documentation/decision gap, not a code defect.
- **F02:** the observed outcome is correct. The lock choreography it describes was not needed; the unlocked read alone is enough.
