## 1. Pull superseders into memory.query hits
- **Hook:** in `query_parts`, after `superseded_hits`, before `newer_first_on_ties` (read_service.py ~277-288). The superseder clues are already authorised in `f.superseded_by`.
- **Selection:**
  - only flagged hits in the top 5, newest superseder first;
  - skip logical ids already present or hidden by D-057; respect `kinds`;
  - at most 2 pulled; depth 1 (a pulled hit is flagged but pulls nothing).
- **Chunk:** the best chunk by lexical rank, then vector distance, else chunk 0.
- **Placement:**
  - directly after the first hit it supersedes, as a normal hit with the additive keys `pulled:"superseder"` and `supersedes:[clue]`;
  - the budget cuts lower hits first; `omitted` and `budget.used` stay exact;
  - the contract stays query/2.
- **Scope:** ON for the public query and for synthesis. OFF in memory.ask's own search, which already pulls superseders (D-184).
- **Tests:**
  - unit: placement, cap, dedupe, kinds, depth, pending vectors;
  - integration visibility matrix: scopes, device_scope, archived, historical valid_at/known_at, pinned links, a hidden superseder never named or pulled;
  - budget exactness; G-SURF unchanged.
- **Review:** a design consult (Astra low) plus the release dual review (it is a visibility surface).
- **Measurement ($0):**
  - an oracle on the fresh copy over about 300 real query strings from the traces, counting flagged hits, missing superseders and pulled hits;
  - 2 blind readers judge up to 30 pulls ("states the current value?").
- **Bar:** ≥ 80% yes, the 10-03 "production budget caps" query surfaces the current values, 0 visibility failures, p95 +10 ms max.

## 2a. Notation variants, narrowed to what both reviews accept
Expansions become an exact-token SET:
- only the path part of a token is expanded;
- the query/fragment boundary is found on the raw token and copied byte-exact;
- scheme and authority are never expanded;
- non-flat brackets block every expansion;
- only whole-segment word alternation and flat `[/x]` `[.x]` `[-x]` expand; numeric alternatives never do;
- a literal is supported by notation only on FULL equality with an expansion, never through the word-boundary or prefix rules.
Every reproducer from consults 97/99 becomes a table test that must DROP. The two real cases (T04/T07) must be KEPT.

## 2b. Extractive main-sentence repair (ceiling first)
- **Trigger:** `claims[0]` is dropped.
- **Candidates:** sentences of the writer's own source excerpts (else all shown excerpts). Never from a superseded excerpt or a fenced block; ≥ 3 words.
- **Score:** content-word overlap with the dropped sentence and the question, plus each supported literal it contains; insert only above a threshold.
- **Form:** inserted VERBATIM, quoted, with its handle; flag `main_repair:"extractive"`; confidence one step lower. No generated text (D-230).
- **b2 (cuttable):** the dangling rule ships only with per-language word lists (EN/DE/TR) and the consult-99 counter-examples as tests.
- **Ceiling ($0):** apply the repair offline to every main_dropped case in the recorded traces; 2 blind readers plus Opus on a split.
- **Bar to build:** n ≥ 8, ≥ 70% helpful, 0 harmful. Otherwise cut 2b.

## 2d. Main's pre-existing literal-check weaknesses (each rule measured and shipped separately)
- Hyphen parts: must appear in order, within one line, ≤ 3 non-word characters apart.
- Nested-bracket tokens: a match glued to `[`, `|` or `]` does not count.
- Digit-less URLs: `://` URLs and absolute paths with ≥ 2 segments become hard literals.

**Offline measurement of 2a/2b/2d:**
- a replay harness runs main's and the candidate's validate_prose over every recorded trace;
- fidelity gate: main's replay reproduces ≥ 99% of the recorded answers;
- 2 blind readers judge every flipped sentence.
- Bars: 2a recovers ≥ 1 true claim and accepts 0 unsupported literals; each 2d rule rejects ≤ 1 true claim and newly drops no main sentence, otherwise it is cut.

## Measurement design (WS-3)
- **Arms:** main HEAD vs r4.3 on the SAME fresh DB, with the same env and the same in-process driver (parameterise its DSN).
- **Paired:**
  - 2a, 2b and 2d are deterministic functions of the writer output, so they replay off the flip set F;
  - F and the drill-change set C run live.
- **Samples:**
  - P1: main ×1 on all 120 questions, with traces.
  - P2: N = qr10 ∪ temporal13 ∪ F ∪ C (cap 35, seeded sampling beyond that); main +2, candidate ×3. That gives ≥ 3 samples per arm wherever the arms differ.
- **Grading:**
  - Sonnet + codex, stricter grade wins; the hold-out uses 3 readers (+ Opus) with the §5.1 rule;
  - both arms shuffled into one packet set with fresh codes; the anchor echo is mandatory;
  - 4 calibration packets per set;
  - only same-DB arms are compared.
- **Pre-registered bars:**
  - noise band = main's min..max over its 3 samples;
  - regression = the candidate's mean below main's min, or its harm sum above main's;
  - gain = the candidate's mean above main's max on the mechanism subset;
  - SHIP an item iff there is no regression and either a gain or a pure tightening with 0 true-claim rejections;
  - cost/ask and p95 within +10%;
  - provider and budget errors are re-asked once and never scored.

## Gates
- **G0:** prereg and threat model committed; replay fidelity ≥ 99%; balances and per-provider $/ask known.
- **G1:** item 1's oracle ≥ 80%; the 2b ceiling met; the 2a/2d audits clean; |N| ≤ 35. A failed ceiling cuts the item, not the release.
- **G2:** the ship bars per item. The first failed end-to-end measurement means a strategic pause and an owner check-in.
- **G3:**
  - dual review (clean `git archive`; at most 2 rounds; a HIGH needs a reproducer; the residual risk goes to the owner);
  - deploy with a snapshot and the rollback path;
  - prod smoke incl. the 10-03 query.
