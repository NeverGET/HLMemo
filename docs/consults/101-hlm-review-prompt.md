# Consult 101 — hlm review + read-only server tool hlm.questions (security review, Astra low + Sol xhigh), round 1 of 2
Worktree root. Review `git diff main..HEAD` (commits be5a6d5 server tool, 28b9fd3 CLI + tests).
What: `hlm review` (LLM-free CLI) lets the owner batch-review open librarian questions and answer them via the existing memory.answer contract (idempotent request ids derived from project+question+decision; --dry-run sends nothing). New read-only client tool `hlm.questions` (registered like hlm.export: not advertised to agents) lists open questions oldest-first with subjects' titles, body heads, verbatim quotes, reason, proposed actions, paging and per-kind counts; requires project read access and claims the same visibility rule as the memory.query notices; writes no events and no access events.
Threat model / rubric (written before the review): HIGH = the tool reveals a question, title, body or quote the caller could not read via memory.query/raw (device scope, grants, class scopes, cross-project), or it is callable/advertised to agents contrary to design, or it writes state; MEDIUM = answer replay/idempotency wrong (a retry applies a different decision), dry-run sends, paging skips/duplicates questions, fallback path leaks; LOW = UX/docs/tests.
Questions: 1. Visibility parity with notices/query/raw for every field returned (titles, body heads, quotes of BOTH subjects in cross-project questions). 2. Registration: truly hidden from agents? callable only by the owner's client? auth. 3. Idempotency of answers. 4. Release impact (additive tool; G-SURF unaffected?).
Output: `## Verdict` (GO / GO-with-fixes / NO-GO), numbered findings (severity, file:line, failure scenario, minimal fix); HIGH needs a reproducer. ≤ 60 lines.
