# D-037 app / DB integration consultation

Scope: R01, F04 API, F15, PostgreSQL transaction_timeout, SDK body cap. Root implementation;
native Astra `read_links` worker independently reviews these changes. No external Opus review claimed.

Decisions and evidence:
- Readiness uses a dedicated short-lived autocommit connection within a 2 s asyncio deadline and
  SQL statement timeout. Middleware uses reserved capacity for authenticated readiness's status gate.
- API checks require_pinned_embed_config at construction and lifespan entry before any binding;
  readiness includes the same embed_config check, including runtime drift.
- Reserve two DB slots in a separate admin pool; the middleware worker selects it for admin bearer
  routes and revoke. The ordinary pool max remains its configured size.
- PG >=17 pools set transaction_timeout=20s by default (ordinary HTTP DB deadline 15s);
  revoke temporarily raises this safety bound together with statement and lock timeouts.
- Installed mcp 2.2 StreamableHTTPSessionManager has a supported max_request_body_size argument
  (local SDK streamable_http_manager.py:95,114). Pass the same configurable 64MiB bound as app,
  retaining 50×64000-character bodies. Worst escaped supplementary Unicode bodies use 38.4MB.
  No SDK monkey-patch or write-model limit reduction. Complete wire cap is explicit in §3.
- Fingerprint uniqueness collision uses §2's random-id fallback, preserving old revoked row/token
  and creating a pending device with a fresh token. Resolved registration records effective fingerprint.
- Trusted proxy allowlist defaults to loopback + 172.18.0.0/16 Caddy bridge used by F05 repro;
  HLM_TRUSTED_PROXY_IPS must match the deployed network. uvicorn automatic proxy rewriting disabled
  so registration can inspect the actual peer and validate forwarded hops itself.

Regression files: tests/integration/test_d037_app.py, tests/unit/test_d037_app.py.
Acceptance evidence is recorded separately after execution.
