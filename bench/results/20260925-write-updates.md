# D-118 client benchmark: does a client LLM fill `memory.write` `updates` correctly? (2026-09-25)

`bench/write_updates/run.py` with the D-094 primary profile `openrouter-gpt6-luna` (reasoning low) as the stand-in client. Synthetic public data (`bench/write_updates/scenarios.py`): 30 UPDATE scenarios (a `memory.query` result showing a 4-statement memory among 2 distractors, then a user fact that changes ONE statement) and 10 CONTROLS (a related fact that updates nothing). The model sees the real `memory.query` / `memory.write` descriptions and input schemas; the `memory_write` call is forced. 3 reps per row, concurrency 4. Scoring: an update is item-correct when it names the gold memory's clue; span-correct when also `old_span` lies inside the outdated statement and contains its key phrase; server-apply = the correct update passes the server's own deterministic checks (`core.write_updates`: revise guards incl. "replacement verbatim in the carrying body", or supersede grounding). Precision is over all predicted updates (controls included).
