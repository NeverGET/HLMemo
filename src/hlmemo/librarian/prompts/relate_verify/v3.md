JOB "relation_check": an independent second opinion on pairs of memory items. Judge each pair on its own; be strict about subject and scope, and judge the CLAIMS, not the wording.
INPUT: {"pairs": [{"id", "A": {"title","text","t_valid","project"}, "B": {"title","text","t_valid","project"}}, ...]}
  t_valid = when the item became true; A is never later than B. project = "same" or "other": whether the two items live in the same project of the owner or in different ones.
  An item can hold several statements (a document section, a list, a multi-fact note). Judge statement by statement.
OUTPUT: {"results": [{"id": "<pair id>", "same_subject": <bool>, "conflict": <bool>, "current": "A|B|both|unclear", "replaces_all": <bool>, "adds_detail": "A|B|none"}, ...]}
  Exactly one result per pair, in INPUT order, "id" copied exactly.

same_subject: true only if a statement of A and a statement of B are about the SAME thing in the SAME scope (same environment, host, service, component, file, version and time frame). Different scopes or merely related topics are false. Items from different projects share a subject only when both state the same general knowledge (a lesson, rule or how-to that applies anywhere); one project's own setup (its hosts, ports, settings, people) is never the same subject as another project's.
conflict: true if a statement of A and a statement of B about that same thing cannot both be true NOW. One conflicting statement is enough, even if the items also say other, compatible things. This covers:
- a changed value (port, version, limit, host, owner, path, count, threshold);
- a reversed or replaced decision or default;
- a plan or step that is now done, dropped or no longer applicable;
- a status that changed;
- a rule narrowed, tightened or replaced in part (e.g. A allows an exception that B no longer allows, or B sets a stricter limit for the same thing).
conflict is false for a paraphrase, a translation, an added detail, progress that leaves the earlier statement true, and a rule next to its documented exception.
HISTORY never conflicts: a dated record of what was observed, measured, found or tried (an episode, a session note, a test or benchmark result, a review or finding of its day, the evidence or status line of a lesson) stays true for its date. If the only clash is with such a record, conflict is false.
current: which item states what is true NOW: "B" if B replaces A (B is later, or B says the state changed), "A" if A replaces B, "both" if both still hold (no conflict), "unclear" if you cannot tell. When unsure, answer "unclear".
replaces_all: true only if current is "A" or "B" AND EVERY statement of the other (outdated) item is outdated by it, so nothing in the outdated item stays true. false if the outdated item also states other things that are still valid, if there is no conflict, or when unsure.
adds_detail: when there is no conflict: "A" if A states a concrete detail about the shared claim that B lacks (a time, number, condition, reason, step or example), "B" if B does, "none" if both say the same thing (a paraphrase or translation). With a conflict, "none".
